下面整理前端构建工具（Webpack + Vite + Rspack + esbuild）整套高频面试题 + 可直接背诵标准答案，按初级、中级、工程化进阶分层，适配你只会 Webpack、准备补新工具的面试场景。

## 一、Webpack 经典必考题（存量项目必考）

### 1. Webpack 整体构建流程

标准答案：

1. **初始化**：读取配置，实例化插件，注册生命周期钩子；
2. **编译（make）**：从 entry 入口出发，调用 loader 依次解析文件，生成 AST，转换代码；
3. **依赖收集**：递归遍历 import/require，构建完整依赖图；
4. **Chunk 拆分**：根据 entry、splitChunks 规则划分 chunk；
5. **代码生成**：把各个 chunk 打包成 bundle，注入 runtime 运行时代码；
6. **输出（emit）**：插件处理资源（压缩、抽离 CSS），写入 dist 目录。

### 2. Loader 和 Plugin 区别

1. **Loader**：文件转换器，只处理单个文件，输入源码、输出转换后代码；执行顺序：从右往左、从下往上；
			例子：babel-loader、css-loader、file-loader。
2. **Plugin**：插件，贯穿整个构建生命周期，能拿到整个编译上下文、chunk、bundle，可做全局操作；
			例子：HtmlWebpackPlugin、MiniCssExtractPlugin、DefinePlugin。

### 3. webpack-dev-server 热更新 HMR 原理

1. 启动 websocket，浏览器和 devServer 长连接；
2. 文件改动触发 webpack 重新编译，生成新 chunk；
3. 服务端推送变更模块 hash 给浏览器；
4. 浏览器发起 Ajax 请求获取更新模块代码，不刷新整页；
5. 执行更新回调，替换模块实例，保留页面状态。

### 4. 常见打包优化手段（必背）

1. **分包优化**
	- splitChunks：第三方包（node_modules）单独拆 vendor chunk；
	- runtimeChunk: single：运行时代码抽离，避免哈希频繁变动。
2. **依赖排除**
	externals：CDN 引入 Vue/React，不打进 bundle。
3. **压缩与资源抽离**
	MiniCssExtractPlugin 抽离 CSS 成独立文件，css-minimizer-webpack-plugin、Terser 压缩 JS。
4. **缓存策略**
	- contenthash：文件内容变哈希才变，用于持久化缓存；
	- cache: filesystem：开启 Webpack 持久化构建缓存，二次构建提速。
5. **多线程编译**
	thread-loader 多进程处理 babel 转译，规避 JS 单线程瓶颈。
6. **Tree-Shaking**
	开启 mode: production + ES Module(import/export)，删除未引入代码；commonjs 不支持。

### 5. Tree-Shaking 生效前提

1. 使用 ES Module（import/export），不能是 require；
2. Webpack 开启 production 模式；
3. package.json sideEffects 标记无副作用文件，防止误删样式、全局脚本。

### 6. mode development / production 区别

- development：不压缩代码、不删除注释、开启 HMR、保留 source-map、不做 Tree-Shaking；
- production：自动开启代码压缩、Tree-Shaking、模块作用域提升、代码精简，优化产物体积。

## 二、Vite 高频核心面试题（现在新项目必问）

### 1. Vite 为什么开发环境比 Webpack 快很多？

标准答案分两层：

1. **Webpack**：不管改哪个文件，都要先完整构建依赖图，全部打包到内存再启动服务，项目越大启动越慢；HMR 需要重新遍历依赖，开销大。
2. **Vite 开发环境架构（原生 ESM）**
	- 不用全量打包，浏览器原生支持 import ESM；浏览器请求哪个文件，Vite 实时单独编译哪个；
	- 第三方依赖预构建：用 esbuild 一次性把 node_modules 里的 CommonJS 依赖转成 ESM，缓存起来；
	- HMR 粒度极细，只更新改动模块，无需重建整张依赖图。

补充：生产环境 Vite 依然用 Rollup/Rolldown 完整打包，速度优势不再像开发环境悬殊。

### 2. Vite 预构建依赖做了什么？为什么需要？

1. 把 node_modules 中 CommonJS 格式包转成浏览器可识别的 ESM；
2. 合并零散小模块，减少浏览器大量网络请求；
3. 强缓存预构建结果，第二次启动无需重新解析。

### 3. Vite 和 Webpack 完整架构对比

|阶段|Webpack|Vite|
|----|----|----|
|开发环境|全量打包进内存，基于 bundle|浏览器原生 ESM，按需即时编译|
|依赖处理|loader 逐个解析|esbuild 预构建第三方依赖|
|HMR|整张依赖图重新构建|单个模块精准替换|
|生产打包|Webpack 自身打包|内置 Rolldown/Rollup|

### 4. Vite 的缺点

1. 大型超复杂项目（上千模块）生产打包速度不如 Rspack；
2. 依赖数量极多时，预构建时间会变长；
3. 兼容旧 IE 浏览器配置繁琐；
4. 很多老旧 Webpack 定制化 loader/plugin 无法直接复用。

### 5. Vite 中的 plugin 和 Webpack plugin 能通用吗？

不能直接通用。

两者插件钩子体系、生命周期完全不同；但 loader 这类单文件转换逻辑，可以单独抽离复用。

## 三、Rust 系构建工具（Rspack、esbuild）高频面试题

### 1. Rspack 是什么？解决了什么痛点？

1. 字节出品，Rust 重写的构建工具，**API 99% 兼容 Webpack**；
2. 解决 Webpack JS 单线程构建速度慢、大型项目打包十几分钟的瓶颈；
3. 内置 SWC 替代 Babel、内置 LightningCSS 处理样式，不用额外安装 loader。

### 2. Webpack 迁移 Rspack 成本高吗？

极低：

1. 配置文件几乎不用改动，ModuleFederationPlugin、splitChunks 等配置字段完全对齐；
2. 绝大多数 Webpack Plugin、Loader 直接兼容；
3. 只需要把启动命令 webpack serve 换成 rspack serve，即可灰度切换。

### 3. esbuild 定位是什么？能直接做完整项目打包吗？

esbuild 只是底层**转译内核**，不是完整应用打包工具：

- 负责 TS 转 JS、语法降级、代码压缩；
- Vite 预构建、tsup 组件库打包底层都调用它；
- 缺少 chunk 拆分、HTML 处理、插件完整生命周期，不能单独打包业务前端项目。

### 4. Turbopack 和 Rspack 区别

1. Turbopack：Webpack 原作者开发，只深度绑定 Next.js，无法独立使用；增量缓存极强，适合巨型 React SSR 项目；
2. Rspack：独立打包器，不绑定框架，Vue/React 通用，Webpack 项目平滑迁移首选，国内大厂普及度更高。

## 四、横向对比必考题（面试官最爱连环追问）

### 1. 新项目选型：Webpack / Vite / Rspack 怎么选？

1. **全新中小型项目**：首选 Vite，开箱即用，开发体验最好；
2. **老 Webpack 存量大型项目**：迁移 Rspack，不改配置、只提速，性价比最高；
3. **极致定制化、超多私有 loader/plugin、古老兼容场景**：继续保留 Webpack，没必要迁移；
4. **Next.js 专属项目**：自带 Turbopack，不用额外选型。

### 2. 现在 Webpack 是不是被淘汰了？

没有淘汰，但不再是新项目默认首选：

1. 存量后台、传统中后台系统海量 Webpack 项目，长期需要维护；
2. 极度深度定制工程场景，Webpack 生态完备无可替代；
3. 只是从「通用首选」降级为「存量维护专用工具」，面试依然必考原理。

### 3. 为什么现在打包工具都改用 Rust/Zig 开发？

JS 是单线程，构建 CPU 密集型任务（AST 解析、代码压缩、依赖遍历）天生性能上限低；

Rust 无 GC、多线程、内存开销小，CPU 密集场景构建速度提升几倍到十几倍，解决大型工程构建卡顿痛点。

## 五、工程化延伸高频题

### 1. tsup 用来做什么？

专门打包 JS/TS 组件库、工具库，底层基于 esbuild，不用复杂配置，只输出 CommonJS + ESM 双格式，不适合业务应用打包。

### 2. pnpm workspaces + Turborepo 作用

Monorepo 工程配套工具，和打包器配合：

- pnpm：包管理器，解决幽灵依赖、磁盘重复存储问题；
- Turborepo：多包并行构建、缓存构建产物，一次性打包仓库内所有子包。

### 3. source-map 几种模式区别

- development：eval-cheap-module-source-map，调试友好，构建快；
- production：hidden-source-map，只生成 map 文件不嵌入 JS，线上不暴露源码，报错可单独解析。

## 六、面试回答精简套路（不会也能答完整）

1. 问到 Webpack：生命周期 + Loader/Plugin + 优化手段；
2. 问到 Vite：开发 ESM 按需加载 + esbuild 预构建 + 和 Webpack 启动速度差异；
3. 问到 Rspack：Rust 性能 + Webpack 配置兼容、低成本迁移；
4. 选型题：分新项目、老项目、定制化场景分开阐述。
