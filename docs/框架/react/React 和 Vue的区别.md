
## 总结

我觉得 主要区别在于 Vue 更注重开发效率和易用性，而 React 更注重数据流的可控性、代码的可维护性以及生态的灵活性。

Vue 更强调开发效率和易用性，它基于响应式系统，能够自动追踪依赖并更新视图，开发者只需要关注数据本身。再加上 `template`、指令和单文件组件等设计，对前端开发者来说上手成本比较低，适合快速开发业务。

而 React 更注重代码的可预测性、可维护性以及生态的灵活性。

React 更倾向于让开发者显式地描述状态和依赖关系，通过 state 驱动 UI 更新，并在 `useEffect`、`useMemo` 等 Hook 中手动声明依赖。以及倾向于单向数据流，开发者只能通过 setState 更新数据

其次，在 UI 的组织方式上，React 使用 JSX 来描述页面结构。JSX 本质上是 JavaScript 的语法扩展，因此可以直接利用 JavaScript 的能力来处理条件渲染、组件组合等复杂逻辑。

我自己的感受是，在一些复杂场景下，比如页面里有很多条件判断、动态配置或者逻辑复用需求时，React 的表达方式会更加灵活。因为它本质上就是 JavaScript，所以很多逻辑可以直接抽象成函数或者组件来组合，而不需要额外去适配模板语法。

最后，从生态角度来说，Vue 更偏向于提供一套相对完整的解决方案；而 React 本身更专注于 UI 层，状态管理、路由等能力都可以根据业务场景自由选择，因此生态会更加灵活。

当然，随着 Vue 3 和 React 的发展，两者的能力其实已经越来越接近了，只是在设计理念和开发体验上仍然存在一些差异。

## React 核心

- 保证复杂系统下的可控性
  - 函数式的思想 ui = f(state)。
    - 优点
      - 单向数据流，明确依赖关系可读，状态驱动 UI，setState 手动触发重渲染
        - 代码的可控性，调试路径清晰
          - 在复杂数据来源和交互的场景下以及长期维护场景下，代码更加清晰可控
            - 降低了调试和维护成本
          - 对比
            - Vue 通过响应式系统自动处理依赖，在简单场景下开发效率更高；
            - 但当依赖关系变复杂时，这些关系是隐式且分散的，调试和维护成本会上升。
            - 而 React 通过显式的状态和依赖声明，把依赖关系变成代码结构本身，使得系统更可读、可控，也更容易演进。
      - html 和 css 可以用 `jsx` 去表达
        - 灵活性，表达能力强，代码复用更加容易
          - 因为 html 和 css 都是 js，所以在项目总有一些小的公共组件拆分的时候更加容易
          - 比如条件渲染和动态结构更容易表达
        - JSX 是语法糖，编译成 `React.createElement`；
    - 缺点
      - 心智负担高
        - 需要手动管理依赖 （降低一些开发效率）
        - 需要开发者参与优化性能
      - 简单场景下过度设计
        - 不如 Vue 直观
  - 通过 fiber 机制，做到了交互的流畅性，避免任务阻塞，保证用户交互可控
- 最小化功能设计
  - 社区优势
    - React 生态更开放，方案选择更多，但也带来了选型成本。
    - 支持跨端（比如 React Native），在需要多端统一技术栈时会有优势。

## vue 的核心

- 核心是降低开发成本
  - 降低开发成本和心智负担，提升开发效率
    - 响应式系统
      - 自动追踪依赖，不需要手写
    - template 和 css 语法更加好上手和清晰
    - 默认性能较优
- 缺点
  - 复杂场景下，数据流不清晰，调试成本上升

## 虚拟 dom 之间的区别

从概念上来说都是虚拟 dom，只是说它们的数据结构、执行模式以及达到的目标都不太一样

| 对比维度 | React（FiberNode） | Vue3（树形 VNode+Block） |
| --- | --- | --- |
| 数据结构 | 单向链表，非递归树 | 嵌套递归树形对象，子节点数组 |
| 执行模式 | diff 可分片、暂停、并发调度 | 同步递归 diff，不可中断 |
| VNode 生成 | 纯运行时构建，无编译预处理 | 编译期静态标记 + 静态提升，减负运行时 |
| diff 遍历能力 | 只能单向从左到右 | 数组随机访问，支持双端、LIS 优化 |
| 更新范围 | 父更新默认子树全量 diff | 响应式精准定位组件，局部 diff |
| 跨端能力 | 协调层平台无关，极易多端复用 | 强绑定模板 DOM，跨端适配成本高 |
| 优化思路 | 调度优先，解决主线程阻塞 | 单次 DOM 操作最优，压缩更新耗时 |

- React
  - 全量更新是 React 无法逃避的宿命（由其不可变数据的哲学决定）
    - React 的哲学是 $UI = f(state)$（UI 是状态的函数）。数据是不可变的
    - 这里的全量更新（组件级别更新，调用 setState 的组件以及其子组件 rerender，包括虚拟 dom 的 diff 和更新），指的是虚拟 DOM（Fiber 树）的重新构建与比对
    - 为了解决这个 " 全量更新带来的卡顿 "，React 团队没有改变全量的机制，而是彻底重构了底层的数据结构，把传统的树结构变成了单向链表，也就是 Fiber 架构（16 版本以后）。
  - 单向链表是 React 拯救性能的武器。它把铁板一块的 " 全量递归 " 打散成了可以随时中断、随时恢复的 " 链表指针跳转 "，从而让 React 既保留了全量更新的简单大脑，又获得了极致流畅的用户体验。

### 1. 破题：一句话定性

> "React 和 Vue 的虚拟 DOM 核心本质是一样的，都是用 JS 对象来描述真实 DOM，以此减少直接操作 DOM 的代价。但它们的驱动哲学不同：React 倾向于‘不可变数据 + 全量运行时检查 + 架构层优化’，而 Vue 倾向于‘响应式数据 + 组件级精准更新 + 编译时强优化’。"

### 2. 核心展开：两大框架的运行时机制（展现深度）

这里需要对比两者在更新范围和数据结构上的不同：

#### 范围与数据结构

- React（大张旗鼓的全量更新）： React 拥抱不可变数据（Immutable），调用 setState 时，React 并不知道也不关心具体哪个属性变了。它的默认行为是自顶向下全量构建一颗新的虚拟 DOM 树并进行 Diff。 为了防止大树全量更新导致浏览器卡死，React 16 把虚拟 DOM 重构成了 Fiber 架构。Fiber 的本质是单向链表结构，它把庞大的更新任务拆分成多个低优先级的 " 工作单元 "，利用浏览器的空闲时间进行可中断、可恢复的异步渲染。
- Vue（精准打击的组件级更新）： Vue 拥有完善的响应式依赖追踪系统（Vue 3 的 Proxy）。当数据变化时，Vue 能够精准地知道哪个组件依赖了它。因此，Vue 的虚拟 DOM 更新被天然限制在组件级别。 因为更新范围小、性能可控，Vue 并不需要像 React 那样引入复杂的异步可中断调度（Fiber 架构），它的虚拟 DOM（VNode）依然维持着传统的纯 JS 树形结构，采用同步渲染。

### 3. 技术细节：Diff 算法与编译时优化（展现专业度）

面试官最喜欢听具体的算法名词，这里要把两者的绝招说出来：

只能识别节点向后追加，节点前移会频繁移动 DOM；

- Vue2 双端四个指针交叉比对首尾节点，大量场景直接原地复用，省去 DOM 移动；
- Vue3 先复用双端逻辑剔除首尾稳定节点，中间乱序部分用最长递增子序列锁定无需移动的节点，做到理论最少 DOM 改动，同时 Vue 还有编译期静态节点标记优化 diff 开销，React 只有运行时 diff。

#### Diff 算法的不同

设计思路 Vue 更倾向于 倾向于在已有节点基础上，通过更精细的比较找到可以复用的节点，并尽量减少节点移动，React 更倾向于 倾向于根据新的 UI 描述重新建立新旧节点关系，通过简单高效的规则判断哪些节点可以复用，并减少 DOM 操作。

Vue 更偏向 " 优化节点复用和移动策略 "，React 更偏向 " 快速建立新旧节点映射并完成更新 "。

Vue 倾向于通过更精细的 Diff 算法减少 DOM 移动次数；React 倾向于通过更简单稳定的算法降低计算复杂度，并配合 Fiber 调度保证用户体验。

- React： 采用从左到右的单向链表遍历比对。在 Fiber 架构下，通过 child、sibling 等指针进行深度优先遍历，遇到节点移动时，通过复用 key 的映射表来标记位置变更。
  - Vue2：子节点用双端四指针，优先头尾交叉匹配，对首尾插入、反转、移动更高效。
  - React：单向 Map diff，用 key 建立哈希表 + lastPlacedIndex 单向判断节点移动，无法高效处理节点前移乱序场景；
    - key 建立身份关系和 Map 查找旧节点
    - lastPlacedIndex 判断移动
    - 单向链表遍历
    - React diff 吃亏只出现在：节点批量前移、中间乱序调换位置；尾部 push、尾部 pop、末尾批量新增删除这些高频场景，它没有任何额外 DOM 开销。（部分场景比较吃亏，但是其实最多的是 向后追加 这种情况是很好的）
    - 所以 `lastPlacedIndex` 的本质可以理解为：
      - 一个单调递增的 " 旧列表位置基准 "，用来判断当前节点是否破坏了已有顺序。
        - 为什么 Map？  
           → 快速通过 key 找旧节点，避免 O(n²)。
        - 为什么 lastPlacedIndex？  
           → 判断哪些节点真的需要移动，减少 DOM 操作。
        - 为什么只单向判断？  
           → 用 O(n) 换取足够好的移动判断，不追求理论最优。
      - 这里新列表是始终递增的，因为是按照新列表的顺序遍历的，所以每次判断都是和前一个节点的数组保持一致的，保证最后整个新列表按照顺序排列
      - 这里 react 的移动，最后是对应 commit 阶段的 dom 节点的 insertBefore 和 appendChild
- Vue：
  - Vue 2 采用经典的双端 Diff 算法（头尾四个指针向中间靠拢比对），这在处理列表两端的操作时非常高效。
  - Vue 3 升级为带有预处理的最长递增子序列（Longest Increasing Subsequence）算法。它先排除头部和尾部的相同节点，再针对中间的无序乱序部分计算出最长递增子序列，确保在 DOM 节点移动时，移动次数绝对最少。
  - 自己总结
    - Vue 2 的双端 diff 就是通过首尾两个指针去做对比，能够快速解决首尾节点变化的情况；但是对于乱序更改的情况，反而是多余的对比。
    - Vue 3 保留了头尾的预处理，解决头尾数据更改场景下的快速 diff；然后对于乱序的列表，也能使用最长递增子序列找到最少的更改次数。（做到理论场景的最小移动）

#### Vue 独有的杀手锏：编译时优化（Compiler-Informed）

这是 Vue 3 极具特色的一点，它通过 Template 编译器在编译阶段为运行时 " 大开绿灯 "，而 React 的 JSX 是纯动态的，很难做这种优化

1. Patch Flags（动态标记）： 编译时识别出哪些节点是动态的、具体哪个属性（如仅 class 或仅 text）是动态的，并打上位运算标记。运行时 Diff 直接跳过静态属性，只 \* 对比变化的部分。
2. Hoist Static（静态提升）： 模板中的纯静态节点会被提升到渲染函数之外只创建一次，更新时直接复用，甚至不需要参与虚拟 DOM 的创建和比对。
3. Block Tree（区块树）： 将动态节点打平提取到 dynamicChildren 数组中，Diff 的时候直接遍历这个扁平数组，直接无视了 HTML 嵌套的静态结构。

### 4. 总结升华（展现架构思考）

最后用一两句话收尾，体现你对技术权衡（Trade-off）的理解：

而 Vue 走的是‘编译器 + 运行时’的混合路子。它通过响应式系统卡住了组件级边界，再通过强大的编译器给虚拟 DOM 注入静态信息，让运行时的 Diff 变得极其轻量。可以说，Vue 的虚拟 DOM 某种程度上已经进化为了‘半静态、半动态’的混合结构。"

1. React 受 Fiber 并发架构、跨端定位约束，Diff 选择了调度优先，用任务分片抹平 DOM 多次移动的性能损耗；
2. Vue 扎根浏览器 Web 场景、自带编译器，同步 Diff 不能中断，只能从算法层面极致压缩 DOM 操作次数，把单次更新耗时压到最低；

## Angular 基本理解

Angular 通过底层强约束拉高了超大型多人后台项目的维护上限，但这套设计天然带来封闭性、高入门成本、场景局限性；

强约束（Opinionated），规定死模块、依赖注入、模板拆分、变更检测，开发者很多场景要顺着框架走，定制化改造阻力大。

追求灵活、技术探索的团队天然排斥 Angular。

Angular 通过一系列强约束，提高了项目代码质量上限，但是换来了很大的封闭性和成本。相比起来，react 只要多一些学习成本完全可以做到，并且一般企业开发不需要有那么大的限制来换取管理成本，性价比低

## 三个框架对比

拉上 Angular 一起看：React 完美卡在中间平衡点

### 梯度分层（自由度从高到低 / 框架强制约束从低到高）

1. Vue（自由度最高，约束最少）

   只提供视图 + 响应式，工程、状态、路由无强制标准，底层数据规则宽松；

   优势：小项目、快速 CRUD 开发效率天花板；

   短板：超大规模团队、人员参差不齐时，代码腐化速度快。

2. React（中间平衡：底层强约束，上层完全自由）
   - 底层硬性约束：单向数据流、不可变状态、Hooks 显式依赖，把最容易失控的数据层锁死；
   - 上层完全放开：路由、状态库、请求、样式方案、构建工具全部自选，没有 NgModule、DI 这类强制架构范式；

取舍：底层保证大型项目的可维护下限，上层保留极高拓展性，既能做后台，也能做 C 端、RN 多端、可视化等各类业务。

3. Angular（自由度最低，全链路强约束）

   不只是数据层，模块划分、依赖注入、表单、Http、模板格式、项目目录全部由框架规定死；

   优势：几百人混合团队、外包多、无专职架构组，不用靠人维持规范；

   短板：重型、学习成本高、生态封闭、无法适配多端 C 端业务，适用场景极窄。

### 三者核心取舍一句话概括

1. Vue：牺牲长期大型项目可维护下限，换取极致短期开发效率；
2. React：牺牲一小部分书写便捷度，用底层语法守住可维护底线，同时保留上层全部灵活度，平衡效率、维护性、业务通用性；
3. Angular：牺牲全部技术灵活度与轻量化，用整套框架强制规则彻底降低多人团队管理成本。

### 对应企业选型逻辑

1. 小型团队、短期后台、快速交付需求 → Vue；
2. 中大型互联网公司，业务混合（C 端 + H5 + 后台 + 跨端）、有基础前端规范能力，项目长期迭代 → React（最优平衡点）；
3. 超大型政企 / 金融、百人前端团队、大量外包、纯内部重型表单系统、项目生命周期十年以上 → Angular。

这也能解释市场现状：React 市场份额远高于另外两者，正是因为它兼顾了大型项目可维护和业务场景通用性，适配绝大多数公司的需求。
