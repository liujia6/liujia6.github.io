下面严格按照 Chromium 官方《A Life of a Pixel（一个像素的一生）》完整流水线，把 PaintLayerTree（渲染层树）、GraphicsLayer（合成层树）、分块 Tiling、光栅化 Raster、GPU 合成 整条链路串讲清楚，区分主线程/合成线程/Viz 进程分工，同时理清两层 Layer 树的递进关系。

## 整体总览（五大阶段）

1. 解析 + 样式计算 → DOM+CSSOM
2. 布局 Layout → LayoutObject 布局树
3. 分层构建：PaintLayerTree（渲染层树） → 划分层叠上下文、确定绘制顺序
4. 合成升级：筛选生成 GraphicsLayer（合成层树），主线程提交绘制指令
5. 合成线程：分块 (Tiling) → 光栅化 (Raster) 生成位图/纹理 → GPU 图层合成 → 上屏输出像素

---

## 阶段 1：解析、样式、布局（主线程，Blink）

### 1.1 解析 HTML/CSS

HTMLParser → DOM 树；CSSParser → CSS 样式规则；JS 执行可修改 DOM/CSS。

### 1.2 样式计算 Recalculate Style

DOM 节点匹配 CSS 选择器，计算最终生效样式，生成ComputedStyle。

### 1.3 布局 Layout（重排 Reflow）

遍历 DOM 生成的 `LayoutObject` 树，计算每个元素精确宽高、坐标、换行、浮动排版，得到每个元素在视口中的几何位置。

>输出：LayoutObject 树，只知道「每个元素在哪、多大」，不知道谁盖谁、该分层绘制。

---

## 阶段 2：构建 PaintLayerTree 渲染层树（主线程，核心分层第一步）

### 2.1 什么是 PaintLayer（渲染层）

划分依据：层叠上下文 stacking context
- 普通流内元素：共享同一个 PaintLayer；
- 触发层叠上下文（`position+z-index`、`opacity<1`、`transform`、`filter`、`will-change`）的元素，单独新建一个独立 PaintLayer。

### 2.2 PaintLayerTree 作用

1. 严格按照Z 轴堆叠顺序排序图层，解决谁在上谁在下的绘制顺序；
2. 每个 PaintLayer 内部递归收集子元素，生成独立的DisplayItemList 绘制指令列表（只记录「在哪画矩形、文字、边框、背景」等绘制操作，没有生成像素位图）；
3. 隐藏元素 `display:none` 不会进入任何 PaintLayer，不参与后续绘制。

### 关键特点

- PaintLayer 是绘制逻辑分层，只决定绘制顺序；
- 一个 PaintLayer 只是一套绘制指令集合，还不是 GPU 可识别的独立图层，绝大多数 PaintLayer 最后会合并绘制，不会单独走 GPU 加速。

---

## 阶段 3：从 PaintLayerTree 升级为 GraphicsLayer 合成层树（Compositing Update）

### 3.1 筛选规则：哪些 PaintLayer 会升级成 GraphicsLayer？

Chromium 合成策略自动判定，满足任意一条就剥离为独立GraphicsLayer（合成层）：

1. 拥有 3D transform / `translateZ(0)`；
2. `transition/animation` 作用在 transform/opacity；
3. `will-change: transform/opacity` 显式声明；
4. video、canvas、iframe、固定定位悬浮层；
5. 滚动容器（overflow:scroll）独立滚动层。

### 3.2 两层 Layer 树核心区别（面试必背）

| 维度 | PaintLayer 渲染层 | GraphicsLayer 合成层 |
|------|-------------------|---------------------|
| 本质 | 逻辑绘制层、层叠上下文载体 | GPU 硬件加速物理图层 |
| 所处线程 | 主线程 Blink | 提交到合成线程 cc |
| 存储内容 | DisplayItemList 绘制指令 | 独立绘制指令 + 变换参数 |
| GPU 关系 | 不独占显存，可合并光栅化 | 单独光栅化为独立 GPU 纹理，独占显存 |
| 数量关系 | 数量多，DOM 层级对应 | 数量更少，多个 PaintLayer 可合并进同一个 GraphicsLayer |

### 3.3 Commit 提交动作

主线程把整棵 GraphicsLayer 树、每一层附带的 DisplayItemList 绘制指令、变换矩阵、透明度、裁剪参数，一次性同步提交给合成器线程（cc 线程）；

主线程即可释放，继续处理 JS、用户交互，后续光栅化、合成全部交给后台线程。

---

## 阶段 4：合成线程：Tiling 分块 + Raster 光栅化（像素真正诞生）

### 4.1 Tiling 分块优化（瓦片策略）

一个 GraphicsLayer 可能超长滚动（长网页），不可能一次性整块光栅化：

- 浏览器把单个合成层切分成固定尺寸小瓦片 Tile（标准 256×256px）；
- 只优先光栅化视口内 + 视口周边预留瓦片，可视区外瓦片延迟/按需光栅化；
- 滚动时动态加载新进入视口的瓦片，极大节省内存和计算量。

### 4.2 Raster 光栅化（指令 → 像素位图/纹理）

光栅化线程池并行执行瓦片任务，有两种光栅化模式：

1. CPU 光栅化（Skia 软件绘制）
			解析 DisplayItemList 绘制指令，在内存中逐像素填充 RGBA，生成 CPU 端位图；后续拷贝进 GPU 显存变成纹理。
2. GPU 光栅化（硬件光栅）
			直接把绘制指令送入 GPU，生成显存内的 Texture 纹理，省去内存拷贝。

✅ 光栅化最终产物：

每个瓦片 = 一张完整像素位图；一个 GraphicsLayer = 一组瓦片纹理，常驻 GPU 显存。

>重要：光栅化只执行一次；图层内容不变时，纹理永久复用，不再重复光栅化。

---

## 阶段 5：GPU 图层合成 + Viz 进程上屏输出最终像素

### 5.1 生成 DrawQuad 绘制四边形

合成线程遍历所有 GraphicsLayer 纹理瓦片，根据层级顺序、transform 变换矩阵、透明度、遮罩，生成 GPU 可执行的 DrawQuad 绘制单元。

### 5.2 Viz 进程 GPU 分层合成（Composite）

1. 顶点着色器：对每个合成层整体做平移、旋转、缩放，只计算图层四个顶点坐标，不碰内部像素；
2. 片元着色器：并行逐像素做图层叠加、透明度颜色混合；
3. 严格沿用 PaintLayer 确定的层叠上下文顺序：底层图层先绘制，上层后绘制，重叠区域上层覆盖下层；
4. 全部图层合并成一张完整屏幕帧缓存位图。

### 5.3 最终输出

合成完成的帧缓冲区图像，经由显卡输出到显示器，屏幕上就出现最终像素，一个像素完整生命周期结束。

## 动态更新场景（动画/滚动）补充（Life of a Pixel 重点）

1. 元素 transform/opacity 动画：不会重排、重绘、重新光栅化；
2. 仅修改对应 GraphicsLayer 的变换矩阵数值；
3. GPU 直接复用已有显存纹理，只重新执行一次图层合成；
4. 全程不阻塞主线程，稳定 60fps 流畅动画。

>反面：修改文字、颜色、DOM 结构 → 触发局部重绘、对应瓦片重新光栅化，开销更高。

---

## 极简串联背诵版（面试口述）

1. HTML/CSS 解析生成 DOM、CSSOM，样式计算后 Layout 得到布局树；
2. 主线程依据层叠上下文构建PaintLayerTree 渲染层树，划分绘制顺序，每层生成绘制指令列表；
3. Chromium 合成策略筛选需要硬件加速的层，升级为GraphicsLayer 合成层树，主线程 commit 提交给合成线程；
4. 合成线程把每个合成层切分成瓦片 Tiling，光栅化 Raster 把绘制指令转为 GPU 纹理；
5. Viz 进程 GPU 按既定层级叠加所有纹理图层，完成合成，输出完整像素到屏幕。

### 一句话分清两层 Layer

- PaintLayer：逻辑绘制分层，管 z-index 堆叠顺序；
- GraphicsLayer：物理 GPU 分层，管硬件加速、独立纹理合成。
